# 服务索引 · Service Index

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

一个**网络感知**的自托管服务导航页。

家里那台机器上跑着十几个服务，问题从来不是"记不住有哪些"，而是**同一个服务在不同网络下地址不一样**：
在家是 `192.168.1.50:8096`，在外面是 `jellyfin.example.com`，连了组网又变成 `10.8.0.5:8096`。
于是要么收藏夹里存三套，要么每次现想。

这个页面的做法是：**看你是用什么地址打开它的，就用对应网络的地址生成所有链接。**

- 🏠 用 `192.168.1.50:5000` 打开 → 所有服务都跳 `192.168.1.50:对应端口`
- 🛰️ 用 `10.8.0.5:5000` 打开 → 所有服务都跳 `10.8.0.5:对应端口`
- 🌐 用 `index.example.com` 打开 → 服务跳各自的穿透 / 反代域名

一套配置，三种网络，链接永远是对的。

![索引页](docs/screenshot-index.jpg)

## 功能

| | |
|---|---|
| 🧭 **网络感知跳转** | 按访问地址自动判定当前网络，卡片上还给出每个网络的直达链接，不可达的置灰 |
| 🟢 **在线状态** | 卡片右上角一个小圆点，实时显示这个服务当前网络下通不通 |
| 🔍 **端口发现** | 扫一遍目标主机，连"这个端口上跑的是什么"一起认出来，勾选即入库（118 条指纹） |
| 🔐 **密码加密传输** | 浏览器提交前用 RSA-OAEP 加密，请求体里没有明文。**纯 HTTP 内网也能用**（自带实现，不依赖 WebCrypto） |
| 📝 **网页内增删改** | 服务、网络都能在页面上改，也可以直接手写 YAML |
| 🖼 **自定义背景** | 传一张图或一段视频当页面背景，跟配置一起存在挂载卷上 |
| 🚀 **零预设** | 首次启动引导你配网络，第一个网络照着你的访问地址自动填好。镜像里不带任何示例数据 |
| 🐳 **一个容器** | 无数据库、无外部依赖，配置就一个 YAML 文件 |

> 界面与文档均为中文。

## 核心思路：为什么要“网络感知”

同一台机器，在不同网络里地址不一样：

| 网络 | 访问方式 | 区分服务靠 |
|------|----------|------------|
| 内网 | `192.168.1.50:端口` | **端口**（同一台机器，host 不变，端口区分） |
| 组网 | `10.8.0.5:端口` | **端口**（同上，只是 host 换成组网地址） |
| 公网 | `xxx.example.com` | **域名**（穿透后端口会变，或用 nginx 反代成域名，每个服务一个域名） |

所以配置里把网络分成两种 `mode`：

- **`port` 模式**（内网 / 组网）：地址 = `网络.host` + `:` + `服务.port`
- **`domain` 模式**（公网）：地址 = `服务.domain`

判定“当前在哪个网络”：把浏览器地址栏的域名/IP 拿来，按 `networks` 列表**从上到下**逐条匹配 `match` 规则，**第一个命中**的就是当前网络。匹配以前端（浏览器地址栏）为准，服务端 `Host` 头只作兜底，因此即使中间隔着反代也能判断准确。

`match` 规则支持三种写法：

- 精确：`example.com`
- 子域名通配：`*.example.com`（匹配 `index.example.com`、`jellyfin.example.com` …）
- 前缀通配：`192.168.*`、`10.*`、`100.*`

## 快速开始

### 方式一：Docker / Dockge（推荐）

```bash
git clone https://github.com/hasong66/service-index.git
cd service-index
docker compose up -d --build
```

用 Dockge 的话，把仓库 clone 到它的 stacks 目录（`compose.yaml` 这个文件名是 Dockge 认的），
然后在界面里点 Deploy 即可。

> `compose.yaml` 里是 `build: .`，也就是在本机构建。目前没有发布预构建镜像。

启动后浏览器打开 `http://<本机IP>:5000`，会走两步引导：

1. **设置访问密码**（只存 scrypt 哈希，明文不落盘）
2. **配置网络** —— 第一个网络会照着「你此刻用什么地址打开的这个页面」自动填好，
   多数情况确认一下直接保存即可。之后随时能改。

进去之后是一张空白的索引页。加服务有两条路：右上角「＋ 添加服务」手填，
或者点 🔍 **端口发现**扫一遍这台机器，把跑着的服务自动认出来勾选入库。

镜像里**不带任何预设的网络和服务** —— 这两样完全取决于你自己的网段，
塞示例进去只会变成你配置文件里的垃圾。

配置文件（`config.yaml`，含服务列表与密码哈希）持久化在 `./data` 目录，删容器不丢数据。

### 方式二：直接用 Python 跑

```bash
pip install -r requirements.txt

# 开发模式（默认 0.0.0.0:5000）
python app.py

# 生产模式（推荐 gunicorn，注意 --preload）
gunicorn -b 0.0.0.0:5000 -w 2 --threads 8 --timeout 300 --preload app:app
```

> ⚠️ 多 worker 时务必加 `--preload`：让主进程先加载一次、生成同一个 `secret_key` 再 fork，否则各 worker 各自生成不同密钥会导致会话（登录态）随机失效。
>
> `--threads 8` 和 `--timeout 300` 是给端口发现用的：那是个 SSE 长连接，扫全端口能跑一两分钟。
> 不加 `--threads` 的话扫描期间这个 worker 干不了别的；不放宽 `--timeout`，gunicorn 默认 30 秒就会把它判死。

设置 / 重置密码也可以走命令行：

```bash
python app.py setpw
```

环境变量：

| 变量 | 说明 | 默认 |
|------|------|------|
| `CONFIG_PATH` | 配置文件路径 | 程序目录下 `config.yaml`（容器内 `/data/config.yaml`） |
| `TITLE` | 页面标题，覆盖配置文件里的 `title` | 空（用配置文件的值） |
| `PORT` | 监听端口（仅 `python app.py` 开发模式有效） | `5000` |
| `HOST` | 监听地址（同上） | `0.0.0.0` |

## 配置说明

完整带注释的示例见 [`config.example.yaml`](./config.example.yaml)。下面是要点。

### 网络 networks

顺序敏感，第一个 `match` 命中者生效。

```yaml
networks:
  - id: lan
    name: 内网
    icon: 🏠
    mode: port
    host: 192.168.1.50
    match: ["192.168.*"]

  - id: mesh
    name: 组网
    icon: 🛰️
    mode: port
    host: 10.8.0.5
    match: ["10.*", "100.*"]

  - id: public
    name: 公网
    icon: 🌐
    mode: domain
    match: ["*.example.com"]
```

### 服务 services

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `name` | ✓ | 服务名 |
| `desc` |  | 一句话描述 |
| `icon` |  | 一个 emoji；留空用名字首字母生成色块头像 |
| `category` |  | 分类，用于分组与筛选（默认“应用”） |
| `port` | △ | 端口；`port` 模式网络（内网/组网）靠它拼地址 |
| `scheme` |  | `http` / `https`；留空时 port 网络默认 http、domain 网络默认 https |
| `tunnel` |  | 是否做了内网穿透 / 反代（复选框） |
| `domain` | △ | 穿透/反代后的域名；`tunnel=true` 时必填，公网网络靠它拼地址 |
| `path` |  | 访问路径，如 `/admin` |

可达性规则：**至少要有 `port` 或 `domain` 其一**。没填 `domain` 的服务在“公网”视图显示为不可用；没填 `port` 的在“内网/组网”视图显示为不可用——页面上会用灰色/划线标出。

### 地址是怎么拼出来的

- `domain` 模式：`(scheme 或 https)://domain + path`
- `port` 模式：`(scheme 或 http)://host:port + path`

### 进阶：同一服务在不同网络其实不在同一台机器

少数情况下，某个服务在内网、组网下分别跑在不同机器上。可在该服务里用 `hosts` / `domains` 按网络覆盖（仅手动编辑 YAML 时用）：

```yaml
- id: adv00001
  name: NAS 管理
  port: 5000
  tunnel: true
  domain: nas.example.com      # 公网默认用这个
  hosts:
    lan: 192.168.1.60        # 内网下在这台
    mesh: 10.8.0.6          # 组网下在这台
  domains:
    public: nas.example.com    # 也可针对某个 domain 网络单独指定
```

未覆盖的网络仍回退到 `networks[].host` 或 `service.domain`。

## 端口发现

顶栏的 🔍 打开。填一个主机、选一个范围，它会对目标做 TCP connect 扫描，
再对**开着的端口**各做一次轻量探测，猜出上面跑的是什么，勾选就能直接加进索引。

扫描过程用 SSE 边扫边推：进度条实时走，识别结果一个个冒出来，随时可以「停止」。

![端口发现](docs/screenshot-discover.jpg)

### 它是怎么猜的

每个开放端口只探一遍，不做暴力尝试：

1. **先静听 0.6 秒。** SSH / FTP / SMTP / POP3 / IMAP / MySQL 这类协议是服务端
   先开口，直接就能拿到 banner。
2. **没人开口就发一个 `GET /`。**
   - 回 `HTTP/` 开头 → 解析状态码、`Server`、`WWW-Authenticate` 的 realm、
     跳转地址、以及 HTML `<title>`（支持 chunked 与非 UTF-8 编码）。
   - 回 TLS 告警或直接断开 → 换 TLS 重连再发一次，顺便把证书里的 CN / SAN 读出来。
     家用设备的自签证书经常自报家门（`synology`、`pve.lan`…），是很好的线索。
   - 回别的东西 → 当 banner 处理。Redis、PostgreSQL、MongoDB 被喂一段 HTTP 请求
     都会回一句很有辨识度的报错，正好拿来认人。

拿到这些「证据」后按优先级判定，界面上会标出可信度：

| 标记 | 依据 | 例子 |
|------|------|------|
| **已识别** | 指纹命中（118 条，覆盖常见自托管服务与数据库/中间件） | 标题里有 `Jellyfin`、banner 是 `SSH-2.0-…` |
| **可能** | 只认出通用中间件（nginx / Apache / Tomcat…），或退而用网页标题当名字 | 标题「家庭影院控制台」 |
| **疑似** | 前面都没戏，只能按端口惯例猜 | 8123 → Home Assistant |
| **未知** | 端口开着，但什么都没探出来 | 只报「HTTP 服务」/「未知服务」 |

标题会先过一遍清洗：`Login`、`404 Not Found`、`index` 这种没信息量的一律不用。
识别为 HTTPS 的服务，入库时会把 `scheme` 写成 `https`（HTTP 的留空走网络默认）。

已经在索引里的端口标成「已在索引」，不会重复添加。非 HTTP 的端口（SSH、数据库…）
标一个「非 Web」——它们也能加进来，但卡片是点不开的。每行右边的 ✎ 可以先改再存。

### 范围与耗时

| 预设 | 端口数 | 大致耗时 |
|------|--------|----------|
| 常用端口 | 151 | 几秒 |
| 1 - 10240 | 10240 | 十几秒到半分钟 |
| 全部 | 65535 | 一两分钟 |
| 自定义 | 支持 `80,443,8000-9000` 这种写法 | — |

### 两个前提

- **扫描是从容器里发起的**，所以只看得到监听在 `0.0.0.0` 上的端口。宿主机上只绑了
  `127.0.0.1` 的服务扫不到——这不是 bug，是它本来就不对局域网开放。
- **默认只允许扫内网地址**（含 `10/8`、`172.16/12`、`192.168/16`、`127/8`、
  `169.254/16`，以及 Tailscale 那种 `100.64/10`），外加 `networks` / `services` 里
  已经出现过的主机和域名。这个接口虽然要登录，但放任它扫任意公网地址等于给自己
  开了个代理扫描器。确实需要的话，把 `config.yaml` 里的 `discover.allow_public`
  改成 `true`。

### 组网 / VPN 地址扫不出东西

**要扫就扫这台机器的真实网卡地址（`192.168.x.x` 那个），别扫组网地址。**

不少组网 / 内网穿透工具（NodeBabyLink、ZeroTier、部分 frp 配置…）用的是用户态
网络栈：你 connect 它的虚拟地址时，它会**先把 TCP 握手完成**，再去问对端有没有人
在听。结果就是任意端口 connect 都成功——扫 65535 个端口能给你报 65535 个“开放”，
一条都不能信。这是那层网络的行为，跟扫描器无关，换 nmap 也一样。

所以开扫之前会先做一次**哨兵探测**：随机挑 3 个高位端口（49152-65500，几乎不可能
真有服务）试连。三个全通，就说明这个地址来者不拒，直接停下并提示你换地址，不会
浪费时间去拉一堆假结果。

---

可调参数都在 `config.yaml` 的 `discover` 段：

```yaml
discover:
  timeout: 0.4          # 单个端口的连接超时（秒）。丢包严重的网络可以调大
  concurrency: 256      # 并发连接数，上限 512
  allow_public: false   # 是否允许扫描公网地址
```

> 长扫描是个 SSE 长连接。Dockerfile 里的 gunicorn 因此用了 `--threads 8`
> （扫描期间同一个 worker 还能处理别的请求）和 `--timeout 300`
> （默认 30 秒会把还在扫描的 worker 判死）。放在 nginx 后面的话，
> 响应已带 `X-Accel-Buffering: no`，进度不会被缓冲成一次性到达。

## 在线状态

每张卡片右上角有个小圆点：

| | |
|---|---|
| 🟢 绿 | 端口通 |
| 🔴 红 | 连不上 |
| ⚪ 灰（呼吸） | 这个服务在当前网络下没配地址，无从探起 |

服务端每 20 秒探一轮，切换网络时立刻重探一次。页面切到后台就停，不会在没人看的时候
一直往外发连接。

探测方式是 TCP connect 上去马上断开，不发任何数据。所以它回答的是**「端口通不通」**，
不是「服务是不是正常」—— 反代后面的域名探 443 通，只能说明反代活着，后面的服务未必。

### 组网地址探不准的问题

一部分组网 / VPN 用的是用户态 TUN 协议栈（Tailscale、ZeroTier 那类的某些实现，
以及各家「异地组网」盒子）。这种栈会**替任意端口完成 TCP 握手** —— 你连一个根本没人
监听的端口，它照样给你回一个成功。对着这种地址探连通性，结果永远是通，一排假绿。

所以每轮探测前会先打几个随机高位端口做哨兵：**全通就判定这个地址不可信**，转而按
networks 的顺序借一个可信网络的地址去探。反正各网络指向的是同一台机器，「端口通不通」
是同一件事，只是内网那条路不会撒谎。借用时悬浮提示里会写明探的是哪个网络，不含糊。

**只有「配了地址、但这地址不可信」才借。** 当前网络下压根解析不出地址的服务（比如没给
它配公网域名），说明它在这个网络下本来就到不了，直接给灰点 —— 借内网地址探出一个绿点，
等于凭空编了个「公网可达」出来。

一个可信的地址都没有，同样给灰点 —— 宁可说不知道，也不发假的绿点。

## 自定义背景

顶栏 🖼 可以传一张图片或一段视频当页面背景：

- 支持 jpg / png / webp / gif / mp4 / webm，单个文件最大 64 MB
- 文件存在 `data/uploads/`，跟 `config.yaml` 一起在挂载卷上，**重建容器不会丢**
- 同时只保留一张，传新的会覆盖旧的；随时可以「恢复默认」退回自带的渐变底
- 设了背景之后，顶栏、卡片、分类标题会自动加深一档，保证亮底图上文字还读得清

项目本身不带任何背景素材 —— 一是不想让仓库为了一段视频胖上几十兆，二是自己挑的图
总比别人塞的合适。

## 与穿透 / 反代配合

本工具只负责“跳转到正确地址”，穿透/反代仍由你现有的工具完成。两种常见接法：

- **端口穿透（如 frp）**：公网侧每个服务一个域名+端口，nginx 再统一成 `https://xxx.example.com`。在服务里勾选 `tunnel` 并填该域名即可。
- **nginx 反向代理**：把内网 `host:port` 反代成 `https://xxx.example.com`，同样填到 `domain`。

把索引页本身也穿透出去（例如 `index.example.com`），就能在外网打开索引、自动按公网域名跳转。

> 建议给公网入口（含索引页）加一层 HTTPS + 基础认证 / 访问控制；本工具自带的密码登录是应用层第一道门，不替代网关层防护。

## 安全说明

### 密码加密传输

浏览器**不会**把密码明文放进请求体。提交前先 `GET /api/pubkey` 取服务端 RSA 公钥，
用 **RSA-OAEP(SHA-256)** 把下面这个小 JSON 加密成一个「信封」，只发密文：

```jsonc
{
  "v": 1,                    // 信封版本
  "f": "login",              // 字段用途：login / setup / current / new
  "p": "<密码明文>",
  "t": 1756280000000,        // 服务端下发的时间戳，超过 5 分钟即失效
  "n": "<一次性随机数>"        // 服务端只认一次，挡重放
}
```

服务端用私钥解开后再走原来的哈希校验。三个涉及密码的接口（`/api/setup`、
`/api/login`、`/api/password`）**只接受信封，明文字段一律拒绝**。

几个实现上的选择，值得留意：

- **没有用 WebCrypto。** `crypto.subtle` 只在安全上下文（HTTPS / localhost）里存在，
  而本项目最典型的用法恰好是内网 `http://192.168.x.x:5000` —— 那里它是 `undefined`。
  所以 `static/crypto.js` 自带了一份 SHA-256 / MGF1 / OAEP / BigInt 模幂实现
  （随机数仍走 `crypto.getRandomValues`，它没有安全上下文限制）。加密结果与 OpenSSL
  的 `RSA_PKCS1_OAEP_PADDING + sha256` 互通。
- **私钥存在 `config.yaml` 的 `transport_key` 字段**（首次启动自动生成 2048 位）。
  放配置里而不是内存里，是为了多 worker / 重启后大家用的是同一把钥匙，不会出现
  「A worker 发的公钥 B worker 解不开」。老配置文件升级时会自动补上这个字段，
  已设置的密码不受影响、无需重设。
- **时间戳用服务端时间**（`/api/pubkey` 一并下发），客户端时钟不准也不会误判过期。
- **一次性随机数记在进程内存里**，所以多 worker（默认 `-w 2`）时它只在“同一个
  worker”范围内生效——重放请求若落到另一个 worker，5 分钟窗口内仍可能被接受。
  没有为此引入 Redis 之类的共享存储，是因为能嗅听到登录请求的攻击者同样能嗅听到
  紧随其后的会话 Cookie，直接复用 Cookie 即可，堵住重放并不会改变攻击者的能力上限。

**这防的是什么，不防什么：**防的是同网段被动嗅听直接读到你的密码明文
（密码往往是复用的，泄露代价远大于一次会话）。**不防**中间人——攻击者仍可劫持会话
Cookie 拿到同等访问权。真正的端到端安全依旧要靠 HTTPS，本机制只是在纯 HTTP 内网
场景下把密码本身保住。

### 其他

- 密码以 **scrypt 哈希**（Werkzeug 默认）存储在 `config.yaml`，明文不落盘。
- 会话 Cookie：`HttpOnly` + `SameSite=Lax`，有效期 30 天。
- 写配置用“临时文件 + 原子替换”，避免并发/中断写坏文件。
- 公网暴露务必走 HTTPS；`config.yaml` 含密码哈希与传输私钥，注意目录权限、不要提交到公开仓库（已在 `.dockerignore` 排除）。
